# 九、并发与网络扩展

本章目标：入门 C++ 并发和 Linux/POSIX socket。并发题要优先保证正确退出、没有数据竞争；网络题基础检查只做语法编译，真实行为需要手动运行验证。

## 题 25：线程安全计数器

实现一个 `ThreadSafeCounter`，多个线程同时调用 `increment()` 时结果必须正确。

### 功能要求

- 共享计数值必须受 `std::mutex` 或等价同步机制保护。
- `increment()` 线程安全。
- `value()` 读取结果也必须线程安全。
- 不允许让多个线程直接访问裸 `int`。

### 演示要求

启动 `4` 个线程，每个线程调用 `increment()` `10000` 次。

基础验收输出：

```text
40000
```

### 自测建议

- 多跑几次，结果应稳定。
- 把线程数量和循环次数调大。
- 思考是否可以用 `std::atomic<int>` 实现。

## 题 26：生产者消费者队列

实现一个线程安全阻塞队列 `BlockingQueue<T>`。

### 功能要求

- `push(value)` 添加数据，并唤醒等待线程。
- `pop()` 在队列为空时阻塞等待，直到有数据可取。
- 使用 `std::mutex` 和 `std::condition_variable`。
- `condition_variable::wait` 必须使用谓词，避免虚假唤醒导致错误。
- `push()` 支持移动传入值。

### 演示要求

一个生产者依次放入 `1` 到 `5`，一个消费者依次取出并输出。

基础验收输出：

```text
1
2
3
4
5
```

### 自测建议

- 先启动消费者，再延迟启动生产者。
- 多个生产者和多个消费者。
- 思考如何设计关闭队列的接口，当前题目不要求。

## 题 27：简易线程池

实现一个固定线程数的线程池。

### 功能要求

- 构造时启动固定数量的工作线程。
- `submit()` 添加无返回值任务。
- 工作线程从任务队列中取任务执行。
- 使用互斥锁和条件变量保护任务队列。
- 析构时停止接收/调度任务，并等待所有线程退出。
- 线程池析构时，已提交任务应尽量执行完成后再退出。

### 演示要求

提交编号 `0` 到 `9` 的任务，每个任务输出自己的编号。

基础验收只检查输出中包含：

```text
task 0
task 9
```

任务执行顺序不要求固定。

### 自测建议

- 提交很多任务，确认析构前都能执行。
- 析构时没有死锁。
- 进阶：`submit()` 在停止后应拒绝新任务或抛异常。

## 题 28：带返回值的异步任务

了解 `std::future`、`std::packaged_task`、`std::async` 的作用，并写一个使用 `std::async` 并行计算两个函数结果的例子。

### 功能要求

- 使用 `std::async(std::launch::async, ...)` 启动两个异步任务。
- 两个任务分别计算 `1..500000` 和 `500001..1000000` 的和。
- 使用 `future.get()` 获取结果并相加。
- 使用足够宽的整数类型保存结果。

### 演示要求

基础验收输出：

```text
500000500000
```

### 自测建议

- 思考 `std::launch::deferred` 和 `std::launch::async` 的差异。
- 让异步函数抛异常，观察 `future.get()` 的行为。

## 题 29：TCP Echo 服务器

使用 Linux/POSIX socket 实现最简单的 TCP Echo 服务器。客户端发送什么，服务器返回什么。

### 功能要求

- 创建 TCP socket。
- 设置 `SO_REUSEADDR`，降低端口复用调试成本。
- 绑定 `0.0.0.0:8080` 或等价地址。
- 调用 `listen()` 和 `accept()` 接收一个客户端。
- 循环读取客户端数据并原样写回。
- 对 `socket`、`bind`、`listen`、`accept` 失败做错误处理。
- 所有文件描述符在退出前关闭。

### 验收说明

检查脚本只做语法检查，因为服务端会阻塞等待连接。

### 手动验证

一个终端启动服务器，另一个终端运行：

```bash
nc 127.0.0.1 8080
```

输入任意文本，应收到相同文本。

## 题 30：TCP Echo 客户端

实现一个 TCP 客户端，连接 `127.0.0.1:8080`，读取用户输入并发送给服务器，然后打印服务器返回的数据。

### 功能要求

- 创建 TCP socket。
- 连接 `127.0.0.1:8080`。
- 从标准输入读取一行或多行数据。
- 发送给服务器。
- 读取服务器响应并输出。
- 处理连接失败、读写失败。
- 退出前关闭 socket。

### 验收说明

检查脚本只做语法检查，因为客户端依赖正在运行的服务端。

### 手动验证

先运行题 29 的服务端，再运行客户端。客户端输入一行文本后，应打印相同文本。

## 题 31：多线程 Echo 服务器

在题 29 基础上改造服务器：每接受一个客户端连接，就创建一个线程处理该客户端。

### 功能要求

- 主线程负责 `accept()` 新连接。
- 每个客户端连接由独立线程处理。
- 每个处理线程负责读取、回写、关闭自己的客户端 socket。
- 线程退出前资源必须释放。
- 可以使用 `detach()` 简化练习，但要理解它带来的生命周期风险；更好的方式是保存线程并在关闭时 `join()`。

### 验收说明

检查脚本只做语法检查，因为服务端会阻塞等待连接。

### 手动验证

同时用两个 `nc 127.0.0.1 8080` 连接服务器，两个客户端都应能得到 echo 响应。

## 题 32：HTTP 请求解析入门

写一个函数解析 HTTP 请求第一行。

### 功能要求

- 定义结构体保存 `method`、`path`、`version`。
- 编写 `parseRequestLine(line, result)` 或等价函数。
- 输入格式示例：`GET /index.html HTTP/1.1`。
- 至少能按空白分隔解析三段。
- 解析失败时返回 `false` 或采用明确错误策略。

### 演示要求

解析：

```text
GET /index.html HTTP/1.1
```

基础验收输出：

```text
GET
/index.html
HTTP/1.1
```

### 自测建议

- 空字符串。
- 只有两个字段。
- 多余空白。
- 进阶：拒绝多余字段。

## 题 33：简易 HTTP 响应服务器

基于 TCP 服务器，实现一个只能返回固定 HTML 的 HTTP 服务器。

### 功能要求

- 监听 `127.0.0.1:8080` 或 `0.0.0.0:8080`。
- 接收浏览器或 `curl` 的连接。
- 读取 HTTP 请求。
- 返回合法 HTTP 响应，至少包含状态行、`Content-Type`、`Content-Length` 和空行。
- 响应体为固定 HTML。
- 关闭客户端连接。

### 验收说明

检查脚本只做语法检查，因为 HTTP 服务端会阻塞等待连接。

### 手动验证

启动服务器后运行：

```bash
curl http://127.0.0.1:8080
```

应看到固定 HTML 内容。
