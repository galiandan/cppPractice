# 十四、工程化、测试与调试

本章目标：补齐工程代码里必须有的测试、参数解析、性能观测和异常安全意识。重点不是框架，而是失败路径可控。

## 题 50：用 `assert` 写单元测试

给一个 `add` 函数和一个 `isPrime` 函数写简单测试，测试失败时程序应立即终止。

### 功能要求

- 实现 `int add(int, int)`。
- 实现 `bool isPrime(int)`。
- 使用 `assert` 覆盖正常和边界用例。
- 测试通过时不输出任何内容。

### 基础验收

程序正常退出，且标准输出为空。

### 自测建议

- `add` 测试正数、负数、零。
- `isPrime` 测试 `0`、`1`、`2`、合数和较大的质数。
- 理解定义 `NDEBUG` 后 `assert` 会被禁用。

## 题 51：命令行参数解析

实现一个程序，支持 `--name Alice --age 18` 形式的命令行参数。

### 功能要求

- 从 `argc`、`argv` 解析参数。
- 只处理 `--key value` 形式。
- 返回 `std::unordered_map<std::string, std::string>` 或等价结构。
- 遇到没有值的 key 时可以忽略或报错，策略要明确。
- 不要求支持短参数、等号参数或引号解析。

### 演示要求

运行：

```bash
./a.out --name Alice --age 18
```

基础验收输出：

```text
name=Alice
age=18
```

### 自测建议

- 参数顺序调换。
- 缺少 `--age`。
- 出现未知参数。

## 题 52：计时工具类

实现一个 RAII 风格的 `ScopedTimer`，构造时开始计时，析构时输出耗时。

### 功能要求

- 构造函数记录开始时间。
- 析构函数计算耗时并输出。
- 使用 `<chrono>`。
- 计时器对象离开作用域时自动输出。
- 输出包含任务名称和耗时毫秒数。

### 演示要求

基础验收使用正则检查输出形如：

```text
work cost 123 ms
```

具体毫秒数不固定。

### 自测建议

- 给不同作用域设置不同计时器名称。
- 思考析构函数中是否应该抛异常。

## 题 53：异常安全转账

实现两个账户之间的转账函数，要求金额非法或余额不足时抛异常，并保持账户余额不被错误修改。

### 功能要求

- `Account` 保存余额，并提供 `balance()` 查询。
- `deposit(amount)` 只接受正数，否则抛出 `std::invalid_argument`。
- `withdraw(amount)` 只接受正数，余额不足时抛出异常。
- `transfer(from, to, amount)` 完成从一个账户到另一个账户的转账。
- 金额非法或余额不足时必须抛异常。
- 转账失败时，两个账户余额都不能被错误修改。
- 基础实现可先验证所有前置条件，再修改余额。

### 演示要求

创建账户 `a=100`、`b=20`，转账 `30`。

基础验收输出：

```text
70
50
```

### 自测建议

- 转账金额为 `0` 或负数。
- 余额不足。
- `from` 和 `to` 是同一个账户时应如何处理，策略要明确。
- 思考如果 `to.deposit()` 可能在 `from.withdraw()` 之后抛异常，如何保证强异常安全。
